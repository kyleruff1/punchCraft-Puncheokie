# Backlog as code

Everything on GitHub (labels, milestones, epics, task/story/spike issues, sub-issue links, Project #5 items and their field values) is derived from JSON in this folder. Both scripts are idempotent: run them any number of times and they only create what is missing (matched by exact title).

## Files

- **`backlog-static.json`** — labels, milestones, and the Project #5 definition (fields, options, iteration, views). Hand-edited.
- **`backlog-issues.json`** — epics and issues. One phase fragment per element in `fragments` (exactly 8, in phase order 0..7), each with an `epic` and its `issues`. The original 152 bodies came from a `punchcraft-backlog` Claude Code session workflow, which is **not checked into this repo**; small additions are appended by hand to the relevant fragment. See "Adding new work" below.
- **`project.json`** — written by `setup-project.mjs`. Captures the project id/number/URL and the field/option/iteration node IDs. Never edit by hand.
- **`setup-project.mjs`** — creates/links the project and its fields, iteration, and views.
- **`seed.mjs`** — creates labels, milestones, epics, issues, sub-issue links, and project field values.

## Usage

Prerequisites: `gh` authenticated (`gh auth status`), Node ≥ 18. Working directory: repo root or `tools/backlog/`.

```bash
node tools/backlog/setup-project.mjs
node tools/backlog/seed.mjs
```

Flags:

- `--dry-run` — print what would be done, mutate nothing.
- `--skip-project` (seed only) — create labels/milestones/issues/sub-issues without touching the project board.
- `--owner <login>` (setup only) — defaults to `@me`.
- `--repo <owner/repo>` — defaults to the origin remote.
- `--sleep <ms>` (seed only) — sleep between mutations to stay under GitHub's secondary rate limits (default 350).

## Adding new work

1. Edit the relevant phase fragment inside `backlog-issues.json` (or add a whole new phase fragment) with a new issue object matching the schema:
   ```json
   {
     "key": "M06-07",
     "milestoneKey": "M06",
     "type": "task",
     "title": "…",
     "body": "…",
     "areaSlug": "ble",
     "priority": "P0",
     "size": "S",
     "sprint": "sprint-1"
   }
   ```
2. Re-run `node tools/backlog/seed.mjs`. Existing issues are skipped by title match; new ones are created, labeled, milestone-anchored, sub-issued under their phase epic, and added to the project with field values.

## Regenerating the backlog from scratch

The issue bodies were generated by a Claude Code session workflow (`punchcraft-backlog`) that fans out one agent per phase against `docs/design-spec.md`. That workflow lives in the session, not in this repo, so a from-scratch regeneration is not reproducible from a clean clone — treat `backlog-issues.json` as the source of truth and edit it directly. Its shape is:

```json
{
  "generatedAt": "2026-08-22T…Z",
  "fragments": [ /* 8 objects, one per phase, in order 0..7 */ ]
}
```

To regenerate, re-run the workflow, then re-run `seed.mjs`. Idempotency guarantees no duplicates.

## Guarantees

- Labels are created with `--force`; description and color are always updated.
- Milestones are matched by exact title.
- Issues are matched by exact title (which is `Mnn-XX <title>` for tasks/stories/spikes and `[EPIC] Phase N — …` for epics).
- Sub-issue links use the GraphQL `addSubIssue` mutation; a repeated link surfaces "already a sub-issue" and is counted under `skipped/existing`.
- Project items are matched by their `content.url`; adding an existing issue returns the existing item.
- Field values are set unconditionally on every run (cheap; keeps state converged if the JSON changes).
